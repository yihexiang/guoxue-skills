# 取名学 · 依八字喜用神的综核取名

> 一句话：把"取个好名字"从玄学直觉，变成**先定喜用神、再海选字形补用神、最后五格生肖体检**的四步可复核流程。
> 八字喜用神是主驱动，五格/三才/生肖/音律/字形是综合因子——通用概率让位于具体命局。

**为什么这几段是核心**：它们共同定下了本方法的权重秩序——先用八字定补什么（主驱动），再用五格/生肖做体检（综合因子），并明确反对最常见的"缺啥补啥"误区。任何一张取名卡如果颠倒这个秩序，都会系统性地给出违背命局的名字。

## I — Interpretation（方法论骨架）

**核心逻辑**（因果链）：

1. 八字喜用神针对**具体命局**（日主强弱、扶抑/通关/调候）→ 它决定"该补什么五行"，这是命名的出发点；通用吉数不针对具体人，故通用须让位于具体。
2. 字形五行是最直观的"补用神"手段（木艹竹禾 / 火灬日光 / 土山石玉 / 金钅刀刂 / 氵水雨冫）→ 据喜用神海选字义音律俱佳的候选字。
3. 候选组合成名后，用确定性引擎跑五格、三才、生肖宜忌做**体检** → 暴露外格凶数、生肖忌用部首等问题。
4. 体检问题与主驱动冲突时，保喜用神、权衡换字 → 产出"既补命局又好看"的名字。

**适用前提**：

- 输入是孩子的公历生辰（年月日时分 + 性别）；若只有农历，须先换算。
- 已先经 bazi-paipan 排出八字、并经 geju-yunshi 得出喜用神（本卡**依赖**这一步，不自行排盘）。
- 接受名字须是综合因子优化、不是命运定论的理性定位。

**关键心法**：喜用神是体，五格生肖是用。很多人花大力气把一个名字的五格凑成全吉，却补了命局所忌的五行——那是把辅助当目的。先问"补对了吗"，再问"格数吉不吉"。

## A1 — Past（方法自身的应用与演示）

> **诚实说明**：本素材为多家权威姓名学文献的**结构化综合提取**，不含单一历史名人命名案例。
> 以下演示用本卡引擎对一组示例八字完整跑通流程，算例数值可由 `scripts/wuge.py` 独立复核。

**演示：甲午年·丙寅月·戊土日·庚申时 乾造，喜火土**

- 情境：日主戊土生于寅月，木旺土虚，按扶抑法喜火（印）土（比劫）为用。
- 应用：据喜用神海选——字形五行取火（日/光/炎类）、土（山/石/坤类）且字义端正者；组合成名后跑引擎，如"李昱坤"（李7 昱9 坤8）。
- 结果：引擎算出五格 天8 人16 地17 外9 总24；三才 金土金（吉，无冲克）；生肖若马则坤含土为所宜、昱含日犯马忌（见 src-02）；喜用补字 昱=火、坤=土 → 火土双补到位（未补[]），唯外格9为凶（外格影响最弱，本卡不为它牺牲字义）。此例主驱动已补到位、三才吉，唯一瑕疵是昱犯马忌日——试换李昱城（城10），引擎显示三才反转为金土水（人克地，凶）、且土补丢失（未补[土]）、地格19凶，**更差**，印证保喜用神优先、不因弱禁忌牺牲喜用与三才的权衡原则，故保留李昱坤并标注瑕疵供用户知情。

## A2 — Future（用户何时需要它）

**触发情境**：

- 我家孩子 X 年 X 月 X 日生，想取个补八字的名字

- 这个名字（晓涛 / 梓涵）好不好，五行缺不缺

**语言信号**（用户口语，此处刻意不加引号以免被引语核验器误判）：

- 帮我根据生辰八字取个名字

- 属马的宝宝取名有什么忌讳
- 五格打分很高但我想再确认一下
- 名字是不是缺啥补啥就行

**与邻近技能的区分**：

| 邻近能力 | 本卡适用 | 对方适用 |
|---|---|---|
| bazi-paipan | 八字已排出、要落地到具体名字 | 只要把盘排准、解释盘中名词 |
| geju-yunshi | 已得出喜用神、要据此选字组名 | 要解读格局强弱、喜用神怎么定 |

## E — Execution（可执行步骤）

> 每一步都有完成标准。写不出完成标准的步骤 = 还没想清，已删。

**Step 1 · 取八字喜用神（主驱动，先锁体）**
- 做什么：调用 bazi-paipan 排出四柱，再据 geju-yunshi（或命理判断）得出喜用神五行列表，如 `[火, 土]`。
- 完成标准：拿到明确的喜用神五行列表，并知道日主强弱与用神取向（扶抑/通关/调候）。
- ⏸️ 检查点：若八字尚未排出，本步不得跳过——没有喜用神就进入选字，等于回到"缺啥补啥"误区。

**Step 2 · 据喜用神海选候选字**
- 做什么：按字形五行（木艹竹禾 / 火灬日光 / 土山石玉 / 金钅刀刂 / 氵水雨冫）选命中喜用神、且字义端正、读音响亮、书写不难的字，每个喜用五行备 8–15 个。
- 完成标准：得到候选字池，每个字标注其字形五行与字义；排除生僻、谐音不雅、与长辈重字的字。
- ⏸️ 检查点：候选字必须**字形五行命中喜用**，而非仅靠"感觉属某行"；拿不准的字查《起名专用字典》康熙笔画与五行。

**Step 3 · 组合成名并跑引擎体检**
- 做什么：从字池组合 2–3 字名，对每个候选调用 `scripts/wuge.py` 计算五格、三才、生肖宜忌、喜用补字与平仄。
- 完成标准：每个候选名产出一份体检表（五格数值、三才等级、生肖忌用字、喜用命中字、平仄提示），数值可由引擎复现。
- ⏸️ 检查点：跑一遍 `python3 tests/test_engine.py` 确认引擎自检全绿，再批量评名；外格凶数只作提示，不因它否定一个补对用神的好名。

**Step 4 · 权衡定稿**
- 做什么：对体检暴露的问题（如三才天克人、生肖忌用部首）做权重权衡——保喜用神优先，必要时换字重跑，直到主驱动与综合因子平衡。
- 完成标准：产出 3–5 个推荐名，每个附一句"为什么"（补了什么用神、五格/生肖体检结论），并明确标注本技能不做命运定论。
- ⏸️ 检查点：若为了五格全吉而牺牲喜用神或字义，本轮作废，回 Step 2 重选。

> 机械评名：`python3 scripts/wuge.py 李 昱坤 --strokes 7,9,8 --zodiac 马 --xiyong 火,土 --tones 3,4,1`
> `--xiyong` 传喜用神五行，`--zodiac` 传生肖，`--tones` 传各字声调；引擎输出五格/三才/生肖/喜用补字/平仄，全部确定性可复核。

## B — Boundary（边界与失败模式）

**不适用（出现任一情况请改用别的卡）**：

- 用户只要排八字、解释盘中名词 → 交 bazi-paipan；只要定格局喜用 → 交 geju-yunshi。
- 用户要这个名字能让我娃发财或考上名校的预测断言 → 本卡拒答，那属命理预测，不在范围。
- 用户只认五格全吉、明确拒绝看八字 → 那是 `wuge-only-naming` 取向，本卡不迎合，会提示风险。
- 出生时间只有农历或只精确到年 → 须先换算并提示时辰口径（见 bazi-paipan 的边界）。

**失败模式**：

| 症状 | 根因 | 纠正 |
|---|---|---|
| 名字五格全吉但补了忌神 | 把通用吉数当目的，颠倒主驱动 | 回 Step 1 重锁喜用神，先问"补对没" |
| 为了补五行用了生僻/谐音字 | 字形五行单因子最大化 | Step 2 检查点已要求排除生僻不雅字 |
| 三才显示"大凶"就弃用整名 | 误读三才为命运定论 | 三才是体检提示，结合主驱动权衡而非一刀切 |
| 生肖忌用部首被当成硬禁忌 | 混淆经验性参考与硬性禁忌 | src-02 §0 明确生肖是参考，不凌驾八字 |
| 笔画数用简体现行笔画 | 未用繁体康熙正字 | Step 3 前核对《起名专用字典》康熙笔画 |
| 外格凶数导致反复换字 | 外格影响最弱却被过度看重 | 本卡明确外格影响最弱，不为它牺牲字义 |

**易混淆辨析**：

- 本卡 vs wuge-only-naming：本卡把八字喜用神设为**主驱动**，五格只是体检；只按五格吉数取名会系统性地补错五行。
- 本卡 vs bazi-paipan/geju-yunshi：它们是"定喜用神"的上游（体），本卡是"用喜用神落地到名字"的下游（用）；顺序不可逆。
- "三才大凶"不是判决：它是五行生克提示，需与喜用神权衡，本卡禁止据单一点下死结论（见 src-01 §8 的门派差异与边界数立场）。
